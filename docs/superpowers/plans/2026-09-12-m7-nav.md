## Task 1 — Focus reducer characterization

Create `player/test-ts/m7-navigation-regression.test.ts` with tests prefixed `M7 NAV`.

Cover the focus reducer with stable IDs under:

- initial focus;
- move next/previous through a bounded list;
- current item removed after refresh;
- list reordered with current stable ID still present;
- empty list;
- repeated identical updates;
- provider/channel ID collisions where the presentation key is expected to include provider identity.

Assertions must verify stable application focus state, not browser `document.activeElement` alone.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 NAV.*focus"
npm run typecheck -w player
```

Any failing required invariant is RED. Passing cases are hardening evidence and require no production edit.

---

## Task 2 — Back closes exactly one presentation layer

Using existing presentation/view test seams, exercise repeated open/close and Back behavior for:

- Home overlays/actions where applicable;
- First Run provider choice/entry presentation;
- Provider Management confirmation and page layers;
- Live TV category/channel/options/EPG presentation layers.

Required assertions:

- one Back action closes or steps back exactly one owned UI layer;
- a confirmation/dialog Back does not also exit its parent surface;
- repeated Back after a child layer closes targets the now-current layer, not a stale one;
- focus restores to a stable valid target after child close;
- no Back/highlight action emits playback intent.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 NAV.*Back"
```

If a failing case can only be repaired in `app-composition.ts` or `live-tv-controller.ts`, stop and report `INTEGRATION FIX REQUIRED`; do not edit the hot zone.

## Task 3 — Refresh/re-render and cross-provider focus restoration

Add deterministic tests for presentation rerenders caused by:

- channel/category reorder;
- Favorites list change;
- EPG present → missing → present;
- provider switch producing colliding channel IDs;
- provider deletion removing the previously focused provider option.

Focus keys must not restore across the wrong provider partition. If the current presentation surface uses a stable key, the test must assert provider + item identity where cross-provider collision is possible.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 NAV.*(refresh|rerender|provider)"
```

Do not change provider business logic to repair a focus-key problem.

---

## Task 4 — Reduced-motion navigation regression

Exercise the existing reduced-motion presentation path with deterministic state/action tests. Reduced motion must not change:

- reachable controls;
- focus order;
- Back/layer semantics;
- explicit-play requirement;

Do not add timing sleeps as the primary assertion. Prefer immediate state/DOM assertions after the relevant action.

Run:


If a visual-only CSS issue is discovered outside the frozen NAV production list, report it to the controller rather than claiming ownership automatically.
