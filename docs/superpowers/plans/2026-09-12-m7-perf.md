## Task 1 — Establish frozen-base large-data characterization

### Files

- Create `player/test-ts/fixtures/m7-large-data.ts`.
- Create `player/test-ts/m7-perf-hardening.test.ts`.

### Required deterministic datasets

Build synthetic data only:

- 1,200 channels for one provider;
- at least 200 categories;
- a second provider with colliding channel IDs to preserve partition checks;
- 48 EPG programs per channel for a representative bounded window;
- Favorites/watch aggregates sufficient to exercise Home projections;
- Turkish Search names including `İ/I/ı/i`, `Ş/ş`, `Ğ/ğ`, `Ü/ü`, `Ö/ö`, `Ç/ç`.

The fixture generator must be deterministic from constants; no random data and no real provider URLs.

### Characterization assertions

Add tests named with prefix `M7 PERF` that prove:

1. Search over 1,200 channels returns deterministic ordering, respects limit, and does not cross provider/category identity.
2. `RepositoryEpgQuery.getCurrent()` makes exactly one `listPrograms` repository call.
3. `RepositoryEpgQuery.getNext()` makes no more than two `listPrograms` calls: one current lookup plus one forward lookup.
4. Home projection remains provider-scoped and output-stable when input order is reversed.
5. large-data fixture construction itself contains no credentials/stream URLs.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 PERF"
npm run typecheck -w player
```

If all assertions pass, record the frozen-base behavior as GREEN and proceed; do not optimize merely because the dataset is large.

If any assertion fails, that failing deterministic assertion is the required RED. Capture the exact test name and failure before touching production code.

## Task 2 — Probe EPG normalization/query and catalog read work

Extend `m7-perf-hardening.test.ts` with instrumented test doubles rather than timers.

Required probes:

- normalization processes each source program once and returns deterministic output under reversed input;
- EPG query work is bounded by repository calls, not multiplied by the number of unrelated channels;
- catalog read/query behavior for one provider does not require repeated full-store reads per returned channel;
- Search performs one category-index construction and one channel traversal per call; assertions must target observable work using instrumented arrays/helpers or repository spies, not elapsed milliseconds;
- Home performs one active-provider channel indexing pass rather than repeated repository access; Home domain is pure, so no new I/O is introduced.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 PERF"
```

A wall-clock number may be printed as diagnostic context, but it must not be the pass/fail threshold unless an already-existing repository benchmark contract requires it.
