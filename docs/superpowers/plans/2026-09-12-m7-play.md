## Task 1 — Rapid zap / last-intent-wins matrix

Create `player/test-ts/m7-playback-regression.test.ts` using injected resolvers, players and deterministic deferred promises/timers. No real network or media playback.

Add tests prefixed `M7 PLAY` for:

- A requested, then B requested before A resolve completes;
- A → B → C rapid requests with completions resolving out of order;
- stale A resolver rejection after B or C is already current;
- stale playback completion/callback after a newer intent;
- repeated request for the same provider/channel.

Required assertions:

- latest explicit play intent wins;
- stale completion never becomes current playback state;
- stale failure never tears down a newer successful stream;
- highlight/navigation alone is absent from the playback path;
- watch-session observation follows committed playback, not stale candidate intent.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 PLAY.*(zap|stale|latest)"
npm run typecheck -w player
```

A failure is RED. Passing behavior is evidence, not a reason to refactor.

## Task 2 — Target failure and bounded rollback

Seed a current successful stream/session A, then request B and force failures at each deterministic boundary supported by the existing seams:

- B stream resolution fails;
- B playback start/load fails before commit;
- B failure occurs after A has been identified as rollback candidate;
- rollback itself fails.

Required assertions must follow existing coordinator contracts:

- B resolution failure preserves A playback and A watch session;
- a failed target never records B as a successful meaningful watch;
- rollback is bounded; no infinite retry/oscillation;
- stale rollback cannot overwrite a newer C request;
- public error state remains deterministic/sanitized.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 PLAY.*(failure|rollback)"
```

Do not edit `live-tv-controller.ts` to orchestrate these tests. Use the frozen coordinator/service seams.

---

## Task 3 — Cross-provider explicit playback invariants

Use providers A and B with colliding channel IDs and distinct stream requests.

Prove:

- provider selection or navigation does not stop/start playback;
- explicit play on B resolves through `ProviderStreamResolver` using B's provider record/credential/adapter;
- B resolution failure preserves A;
- successful B commit transitions the watch observer to B only after playback commit;
- late A/B callbacks are partitioned by the active intent/session and cannot corrupt the other provider.

Synthetic credentials may exist only in in-memory test doubles and must not be logged or serialized into ordinary structured storage.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 PLAY.*provider"
```

If the failing integration invariant is only repairable in `create-live-tv-runtime.ts`, `live-tv-controller.ts`, `app-composition.ts` or `browser-app-dependencies.ts`, stop and report `INTEGRATION FIX REQUIRED` with the exact failing test and minimum hot-zone file.

## Task 4 — Watch playback-session regression

Exercise `playback-session-observer.ts` with deterministic timestamps/timers around:

- very short zap;
- meaningful watch threshold path already defined by current watch contracts;
- target failure before commit;
- rollback to prior stream;
- provider switch after successful explicit play;
- stale stop/completion notification.

Required assertions:

- very short/transient candidates do not become false meaningful watches;
- duration/open counts remain attributed to the committed provider/channel;
- rollback does not double-count opens or duration;
- stale events cannot close/credit the wrong current session.

Run:

```bash

```
