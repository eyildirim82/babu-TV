## Task 1 — Characterize current schema and repository isolation

Create `player/test-ts/m7-storage-migrations.test.ts` using the same IndexedDB/fake store strategy already used by existing persistence tests.

Add tests prefixed `M7 MIG` proving:

1. provider records, catalog rows, EPG, Favorites and watch state remain provider-scoped even when channel IDs collide across providers;
2. deleting/replacing data for provider A does not remove provider B data;
3. provider/catalog/EPG replacement preserves user-owned Favorites/watch state unless an existing explicit cleanup contract says otherwise;
4. StructuredStore rejects/contains malformed access according to current contract rather than leaking arbitrary native serialization;
5. no credential/password/token field is introduced into structured records by migration or repair behavior.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 MIG"
npm run typecheck -w player
```

Any failure is RED. Passing behavior is recorded without a production edit.

## Task 2 — Exercise upgrade/migration behavior

Using the repository's existing IndexedDB test seam, create deterministic pre-upgrade data representing the previous supported structured shape/version, then open through the current `IndexedDbStructuredStore` path.

Required assertions:

- required stores/indexes exist after upgrade;
- provider A and B records survive independently;
- catalog and EPG data remain partitioned by provider;
- Favorites and watch state survive a non-destructive schema upgrade;
- removed/obsolete store behavior follows the current schema contract;
- opening an already-current database is idempotent and does not duplicate records;
- upgrade failure is surfaced as a fixed application/storage failure rather than raw native data.

Do not invent a new schema version merely to create work. If the frozen base has no migration step beyond the current version, construct only valid historical versions supported by the current implementation/tests and prove reopen/idempotency.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 MIG.*(upgrade|migration|reopen)"
```

If a required test cannot be expressed without changing application composition, stop and report the test seam issue; do not edit a forbidden hot zone.

## Task 3 — Corruption and malformed-record recovery

Seed malformed structured records using the lowest existing test seam that bypasses repository validation, then read them through the owning structured repository.

Cover at minimum:

- malformed provider record;
- malformed/partial catalog channel/category row;
- malformed EPG row;
- malformed Favorite row;
- malformed watch-state row.

The expected behavior must be derived from existing repository/storage contracts and current safe degradation rules. Do not silently define destructive data deletion as the default recovery strategy.

Required invariants:

- one corrupted provider-scoped record must not corrupt another provider partition;
- recovery must not erase unrelated valid user-owned state;
- malformed records never become credential persistence;
- raw IndexedDB/native exception strings are not required public API.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 MIG.*corrupt"
```

A failing assertion is the RED for a minimum persistence fix.
