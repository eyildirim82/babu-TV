## Task 1 — Build deterministic failure transport/adapters

Create `player/test-ts/m7-provider-failures.test.ts` using injected fake transports/adapters only. No real network calls.

Add exact scenario groups prefixed `M7 FAIL`:

- HTTP 401;
- HTTP 403;
- HTTP 404;
- HTTP 500;
- rejected fetch / offline;
- timeout/abort path supported by the current HTTP seam;
- malformed Xtream payload/response;
- malformed or empty M3U/provider response where the current provider contract requires content;
- EPG source failure;
- provider sync failure with an existing useful catalog;
- background/explicit refresh failure with existing useful EPG/catalog cache;
- re-entry preflight failure before credential commit.

For each case assert the current product invariant, not internal implementation detail:

- error exposed to caller is fixed/sanitized;
- raw response body/native/fetch text is not surfaced;
- username/password/query/token values used in the synthetic input are absent from error text;
- a failed refresh does not erase a previously usable cache;
- durable Favorites/watch state is not touched by a provider refresh failure;
- failed re-entry preflight performs no credential/catalog/provider write.

Run:

```bash
npm run test:ts -w player -- --test-name-pattern="M7 FAIL"
npm run typecheck -w player
```

A failing assertion is RED. A passing scenario is characterization evidence and must not trigger speculative production edits.
